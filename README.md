# 地勘取芯数据入仓演示（FastAPI + SQLite）

岩芯存在缺失时，样品孔深不能按岩芯实长直接累加：相邻岩芯段之间的缺失长度只给出
上下限，因此每个段、每个样品的孔深都是一个**可行范围**。本应用对取芯回次做约束
求解，只有在**所有可行排布中都完整落入同一地层**的样品才连同层位写进入仓 CSV，
其余样品仅展示起止孔深各自的可行范围与未入仓原因。

深度一律使用**整数毫米**，所有区间**左闭右开**。

## 一、模型与判定规则

设回次有 n 个岩芯段，段实长 L_j，段 j-1 与段 j 之间缺失 g_j ∈ [low_j, high_j]。
令 P_0=0、P_j = g_1+…+g_j，则：

- 段 j 起点孔深 = 回次起始 + P_j，终点孔深 = 起点 + L_j；
- 回次起止孔深之差必须容纳全部岩芯：P_{n-1} ≤ 回次进尺 − 实长合计
  （回次顶部/终孔处的剩余缺失为非负自由量，不要求填到终孔）；
- 数据员录入的“段起点实测孔深”等价于等式约束 P_j = 实测值 − 回次起始。

求解器对每个前缀 P_j 分别求全部可行排布下的最小值/最大值（线性规划的部分和紧边界，
分“等式块”和末端“开放块”处理），再换算为段与样品的起止孔深可行范围。

样品在段内位置 [a, b) 固定，故：

- 起点可行范围 = [段起点_lo + a, 段起点_hi + a]
- 终点可行范围 = [段终点_lo − (L−b), 段终点_hi − (L−b)]
- 样品可能占据的全部整数孔深为 [起点_lo, 终点_hi − 1]；该范围内没有地层分界时，
  层位在所有排布中唯一，样品连同层位写进入仓 CSV，否则暂不入仓并展示原因。

## 二、功能

- 导入取芯回次：回次起止孔深、按序岩芯段实长、段间缺失上下限、段内样品编号/位置/
  化验值、地层分界与层位名称（粘贴 JSON 或上传 .json 文件，页面附演示数据）。
- 详情页展示：各段起止孔深可行范围、每个样品的起止可行范围、入仓判定与原因、
  生效入仓清单、更正历史。
- 数据员录入/更正岩芯段起点实测孔深：提交后整份回次重新求解，**整份替换**供数表，
  版本号 +1。
- 约束无解或页面版本过期：明确提示原因，事务回滚，**当前供数原样保留**。
- 生效数据保存在 SQLite（`runs / measured_starts / supply_rows / correction_log`
  等表）；入仓 CSV 为 utf-8-sig，Excel 可直接打开。

## 三、混样化验单与缺测值复原

部分岩芯原样化验值遗失，实验室只找回**两两等量混样**的化验单。数据员在回次详情页
按单号**录入 / 更正 / 撤销**化验单，每单填写本回次两个不同的原样编号和混样均值：

    原样A + 原样B = 2 × 混样均值      （等量混样，均值为算术平均数）

规则与保证：

- **精确十进制**：参与推算的数值一律为非负十进制（`decimal.Decimal` 精确处理，
  不接受负数与科学计数法）；原样值空白表示缺测，非空白但无法解析的值不参与推算
  并在页面上单独提示。
- **复原清单**：结合现行化验单与已有原样值联立求解（样品为顶点、化验单为边，
  每个连通块分别按“已有值锚定 / 奇环钉死 / 非负区间夹逼”处理）。在所有非负解中
  **取值唯一**的缺测样品单列展示并给出复原值与依据；其余缺测样品标为**待补测**
  并说明原因（未涉及任何化验单，或取值区间不唯一）。
- **矛盾拒绝**：录入/更正若与现行化验单或已有原样值矛盾（等式冲突、推出负值、
  非负区间为空），请求被拒绝并**说明具体原因**，当前化验单与复原结果保持不变。
- **撤单即重算**：撤销只去掉一条约束，必然成功；撤单后不再唯一的值自动从复原
  清单移出、转为待补测。
- **并发安全**：每次变更在单个 `BEGIN IMMEDIATE` 事务内对“当前全部有效化验单”
  重算校验，并发请求被串行化，相互矛盾的化验单不可能同时生效。
- **一致性**：复原结果不落库，每次读取时由同一事务快照内的化验单与供数载荷现算，
  页面上的化验单和结果始终对应同一份有效数据；化验单持久化在 SQLite
  （`assay_slips / assay_log` 表），重启后仍可查询。

## 四、启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

首次启动且库内无回次时，容器会自动载入演示回次 `RUN-2026-01`（S2/S4/S5 缺测）
与三张演示化验单 H001–H003（设 `APP_SEED_DEMO=0` 可关闭）。

SQLite 数据库与数据目录保存在命名卷 `coring_data`（容器内 `/data`），重启不丢数据。
停止与清理：

```bash
docker compose down          # 停止，保留数据卷
docker compose down -v       # 同时删除数据卷
```

本地不使用 Docker 时也可直接运行（Python 3.11）：

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 演示：从回次页看撤单如何改变复原结果

1. 打开 `http://localhost:8000/runs/RUN-2026-01`。“缺测样品复原结果”中
   S2=0.08、S4=0.27、S5=1.05 均已唯一复原（依据已有值 S1=0.12 与化验单
   H001–H003 的链式联立）。
2. 在化验单表中点击 **H002 的“撤销”** 并确认：S4、S5 立即从复原清单移出、
   转为“待补测”（仅剩 H003，取值区间不唯一），S2=0.08 仍保留。
3. 再撤销 **H003**：S4、S5 变为“没有任何化验单涉及该样品”。
4. 试试矛盾拒绝：录入单号 `H100`、原样 S1 与 S3、混样均值 `9.9`，
   提交后被拒绝并提示“两者之和为 0.43，不等于该单要求的 19.8”，
   当前化验单与复原结果不变。

## 六、目录结构

```
app/
  engine.py            # 录入校验 + 可行区间求解 + 地层判定（纯函数，无框架依赖）
  assay.py             # 混样化验单联立推算：唯一复原/待补测判定与矛盾解释（纯函数）
  storage.py           # SQLite 持久化、整份替换事务、BEGIN IMMEDIATE 化验单事务、入仓 CSV
  main.py              # FastAPI 路由与 flash 提示、演示数据种子
  templates/           # Jinja2 页面（列表/导入/详情）
  demo_payload.json    # 导入页预填演示回次（S2/S4/S5 缺测）
  demo_slips.json      # 演示化验单 H001–H003（APP_SEED_DEMO=1 时载入）
tests/                 # pytest 自测
Dockerfile, docker-compose.yml, requirements.txt
```

## 七、录入 JSON 字段

| 字段 | 含义 |
| --- | --- |
| `run_id` | 回次编号（主键） |
| `start_depth` / `end_depth` | 回次起止孔深，整数毫米，左闭右开 |
| `segments[].length` | 岩芯段实长（毫米，正整数，按取芯顺序） |
| `segments[].samples[]` | `sample_no`、段内 `start/end`（左闭右开）、`assay` 化验值（空白表示缺测） |
| `gaps[]` | 段间缺失 `low/high`（毫米），数量 = 段数 − 1 |
| `boundaries` | 地层分界深度（严格递增，位于回次区间内部） |
| `layers` | 层位名称，数量 = 分界数 + 1 |
| `measured_starts[]` | 可选，`seg_index`（从 0 起）与实测起点孔深 `depth` |
